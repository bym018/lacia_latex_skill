# 内容编排规则

## 1. 封面与"如何使用这份讲义"

封面：只有标题（可加一条细线），没有副标题。

反例：标题下一行"文法 · 自动机 · 语法分析 · 语义翻译 · 代码生成与优化"，再加一排"字符流→单词流→语法树→…"的示意框。这种一眼就是模板化填充，读者得不到新信息。

如果确实想给出全书概览，放进"如何使用这份讲义"一节，写成连贯的文字：全书主线是什么、各部分回答什么问题、怎样读、色块含义。

## 2. 无用文字

删除一切不服务于读者学习的元信息：
- "依据 2026-xx-xx 本地课件整理"
- "配色：Lacia Pale Violet，另有暗色版"
- "以本地 9 份课件（共 664 页）为主线重制：…"
- 对工具、模板、生成过程的任何说明

判断标准：这句话删掉后，读者的学习有损失吗？没有就删。

## 3. 独立成立

讲义是独立使用的 PDF，读者手上只有这一份文件。

不得出现：
- 脚本或文件路径，如 `verify/verify_examples.py`
- 外部链接、示例 URL
- "详见课件原图 / 课件第 N 页"这类指向读者没有的资料的引用
- 依赖另一份文档才能读懂的省略

需要的结论、推导、数据直接写进正文或附录。确有出处需要保留时，写成文字说明（教材名、章节），不写路径。

## 4. 每章概述

概述是可选的。写，就写成完整的一段，包含四件事：

1. 上一阶段（或上一章）的做法是什么；
2. 那种做法的上限或局限在哪；
3. 本章换了什么思路、用在何处；
4. 读完应当能做什么（可验证的能力，不是"了解…"）。

不合格的概述：几个关键词；一张图；"本章介绍 X 的基本概念"这种可套用任何章节的话。

示例见 `assets/template/chapters/01-binary-search.tex`。

## 5. 其他编排习惯

- 先说"为什么"再给结论，再给例子；先直觉后形式化。
- 每章末尾可放自测，题目要能从本章内容推出，答案若给出须独立可验证。
- 勘误色块只用于指出原始资料的错误，并给出修正；不要用来写"注意"。

## 6. 专用记号

读者常跳着读，会忘记记号含义。符号密集的讲义配"每节首次出现的页边旁注 + 附录符号表"，二者都由 `symbols.tex` 生成，用法见 `symbols.md`。

- 正文专用记号一律用登记过的宏，不裸写。
- 一个字形两种含义时拆成两个宏，在符号表里并列写清区别。反例：$\Rightarrow$ 既表示"直接推导"又表示"已标 ⇒ 标记"，跳读时无法区分。
- 释义取自正文的定义；对不上说明正文缺定义，先补正文。
